# 多目标暖启动（Pareto 前沿迁移）

问题：把上一次多目标战役的 **Pareto 前沿**迁移到新战役，有没有用？等预算对比
（`moo_constrained`，源 20 次、目标 20 次、batch 4、`cqehvi`、seed 0–4）：

| 臂 | 迁移点数 | 可行 HV（均值） | 可行前沿点数 |
|---|---|---|---|
| 不迁移（baseline） | 0 | 642.66 | 9.6 |
| `top_k=3, r=1.0` | 3 | **645.89**（+0.50%） | 10.6 |
| `top_k=5, r=1.0` | 5 | 645.19（+0.39%） | **11.6** |
| `top_k=5, r=0.5` | 5 | 645.96（+0.51%） | 11.6 |

## 结论（诚实）

1. **方向稳定但幅度不大**：5 个种子下三种迁移设置都优于 baseline，可行 HV 涨 ~0.4–0.5%；
2. **前沿点数涨得更明显**：9.6 → 11.6（+20%），说明暖启动主要让前沿更“铺开”，
   而不是把最优往上顶；
3. `prior_reliability` 1.0 与 0.5 没有差别（说明同问题、同规格的源本身可信）；
4. 因此：**多目标场景建议开暖启动**（`transfer_from` 会自动按非支配前沿选点），
   但不要期待大幅提升；若源与目标问题不同，先跑 `condopt transfer-audit` 再决定可靠度。

## 多保真 + 多目标：暖启动没有收益（5 seeds）

同一问题换成 `mf_moo_constrained`（源/目标各 20 次，batch 4）：

| 臂 | 迁移点 | 可行 HV（均值） | 可行前沿点数 |
|---|---|---|---|
| 不迁移（baseline） | 0 | **626.92** | 5.2 |
| `top_k=3, r=1.0` | 3 | 626.27（−0.10%） | 5.8 |
| `top_k=5, r=1.0` | 5 | 626.68（−0.04%） | **6.8** |
| `top_k=5, r=0.5` | 5 | **620.94（−0.95%）** | 6.6 |

**结论**：多保真场景下暖启动对交付 HV 是**中性到轻微有害**——`r=1.0` 基本持平，
调低 reliability 反而掉近 1%。前沿点数仍然增加（+11–31%），即“铺开但不更高”。
因此 `prepare.prior` 在多保真 + 多目标时给出**谨慎建议**：默认不开，需要铺开前沿时才开，
且只用 `reliability=1.0`。

可能原因：迁移进来的是全保真点，而新战役的多数观测在低保真档位，
先验在成本加权采集里占不到便宜，还会挤压低保真探索。

### 为什么是“中性”？关键在预算记账

`transfer_from` 导入的观测**按评价次数占用目标预算**（返回值新增 `budget_charged` / `cost_charged` / `remaining_after_transfer`，审计用）。本实验各臂的总观测数都是 ~20：

| 臂 | 平均总观测 | 其中迁移 |
|---|---|---|
| baseline | 19.4 | 0 |
| k3 r=1.0 | 18.0 | 3.0 |
| k5 r=1.0 | 20.0 | 5.0 |
| k8 r=1.0（含低保真） | 20.0 | 6.6 |

所以暖启动的净收益 = **源点质量 − 目标自己测同样多点数的质量**。
同一个问题、独立的源战役，两者统计上等价 → 中性（±0.1%）；
迁移更多点（k=8，含低保真）时略正：**629.09 vs 626.92（+0.35%）**。

`reliability` 调低是唯一明确的负项（k5 r=0.5：620.94，−0.95%），因为它在数学上就是
把先验信息打折，而点数照样占预算。

低保真源点只在**成本预算**口径下更省（本次目标 study 没有 `cost_budget`，所以没差别）。

### 多保真建议（修正版）

| 设置 | 可行 HV | 结论 |
|---|---|---|
| 不开（baseline） | 626.92 | 默认 |
| k3 r=1.0 | 626.27 | 中性 |
| k5 r=1.0 | 626.68 | 中性 |
| **k8 r=1.0 + 含低保真** | **629.09** | 略有正收益（+0.35%） |
| k5 r=0.5 | 620.94 | 负收益，不要调低 reliability |

## 复现

```powershell
py -3 scripts/benchmark_transfer_moo.py --source-budget 20 --target-budget 20 --seeds 0 1 2 3 4
```

## 修复平台期缺陷后的重测（Round 278，3 seeds）

`moo_constrained`，source/target budget 20，batch 4：

| 臂 | 可行 HV | 前沿点数 | 导入条数 |
|---|---|---|---|
| baseline | 640.78 | 9.33 | 0 |
| transfer k=3, r=1.0 | **645.44（+0.73%）** | **11.33（+21%）** | 3 |
| transfer k=5, r=1.0 | **645.72（+0.77%）** | 11.33 | 5 |
| transfer k=5, r=0.5 | 643.64（+0.45%） | 11.67 | 5 |

结论与修复前一致（小幅正收益、前沿点数 +21%），幅度略好；`prior_reliability=0.5` 的 HV 略低但
前沿点数最多 —— 与“打折先验会削弱数值收益、但保留多样性”的直觉一致。
