# 审计阈值校准：低置信度下不能给“完全信任”

## 实验（`scripts/benchmark_audit_calibration.py`）

用**受控质量**的源（相同 / 轻微噪声 / 偏差 −12 / 打乱标签）向目标迁移，比较
`assess_transfer` 给出的建议可靠度与**实测**迁移收益（`ackley10`，budget 20，2 seeds）：

| 源质量 | 审计分数 | 实测 Δ vs 冷启动 |
|---|---|---|
| identical | 0.60 | +1.06 |
| mild_noise | 0.65 | **+3.18** |
| biased(−12) | 0.65 | **−0.54** |
| shuffled | 0.30 | +0.43 |

## 结论（负面为主）

1. 审计**分不出“有偏源”和“轻微噪声源”**（都是 0.65），而两者收益一正一负（+3.18 / −0.54）；
2. 相同源（0.60）甚至低于轻微噪声源 —— 6 条目标观测时目标代理太弱，排序接近噪声；
3. 只有**打乱源**被明显压低（0.30 < 0.5），即审计对“完全不一致”有效，对“中等偏差”无效。

> 在 `mixed_reaction` 上还出现**上限效应**（冷启动已到 101.2，optimum 102）→ 换到 `ackley10` 才有空间。

## 处置（有依据的行为修正）

**低置信度审计的建议值封顶 0.6**（原来可给 1.0）：

- 依据：上表里“有偏源”在 6 条目标观测时同样拿到 0.65（按旧规则 = 1.0 完全信任），却带来 −0.54；
- 实现：`assess_transfer` 在 `confidence == "low"` 且建议 >0.6 时降到 0.6，返回
  `capped_by_low_confidence=true` 并在 `reason` 里写明“封顶 0.6”；
- 未采纳的方案：把“目标观测 <8 就拒绝给出建议”（会破坏交付流程且现有低样本告警已覆盖）。

## 复现

```
py -3 scripts/benchmark_audit_calibration.py --problem ackley10 --budget 20 --seeds 0 1
```

## 稳定性说明（必须写清）

上表的 0.65 是在 **`--source-points 30`** 下得到的；用默认 24 个源点时，同一个有偏源审计降到
**0.30**（落到“打折/避免”区间）。也就是说：

- **有偏源的审计分数本身不稳定**（0.30 ~ 0.65），既可能被正确压低、也可能被误判为“可信任”；
- 因此处置不是“改阈值”，而是**低置信度时不给 1.0**（封顶 0.6）——即使分数偏高也不会被当成完全信任；
- 可重跑声明的参数固定为产生误判的那组（`--source-points 30`），这样回归的是**失败模式**而不是平均值。

无论分数高低，**有偏源的实测收益都是负的**（−0.54），这条在所有配置下稳定。

## 阈值扫描：审计对“偏差大小”完全不敏感（Round 284）

用细粒度偏差网格（bias 0 / −3 / −6 / −9 / −12 / −18，噪声 σ=2）跑
`--fine --source-points 30 --budget 20 --seeds 0 1`：

| 源偏差 | seed 0 审计 | seed 0 Δ | seed 1 审计 | seed 1 Δ |
|---|---|---|---|---|
| 0 | 1.0 | **+2.49** | 0.6 | **+1.33** |
| −3 | 1.0 | −0.51 | 0.6 | −1.33 |
| −6 | 1.0 | +0.26 | 0.6 | −1.33 |
| −9 | 1.0 | +0.26 | 0.6 | −1.34 |
| −12 | 1.0 | +0.26 | 0.6 | −1.34 |
| −18 | 1.0 | +0.26 | 0.6 | −1.34 |

**关键结论**：

1. **审计分数在同一 seed 内对所有偏差完全一样**（1.0 或 0.6）——它测的是“源与目标证据是否相关”，
   而系统性偏差不改变秩相关，所以**审计对偏差大小天然盲**；
2. 阈值扫描显示“最优切点”0.65 的准确率 0.833，**其收益完全来自 seed 之间的差异**（seed 0 分数高、
   收益也高），同一 seed 内没有任何分辨力；把它当作“选 reliability”的依据是不成立的；
3. **收益在偏差仅 −3 时就翻负**（此前只测过 −12）——即“源看起来一致”是很弱的证据；
4. 与“打乱源能被打到 0.3”一致：审计**只能识别完全不一致**，不能识别中等偏差。

处置（决策层）：`reliability_grade` 的 trust 档补充“**审计分高 ≠ 收益为正**（实测偏差 −3 就翻负）；
先用 top_k 1–3 观察两批再放大”，配合“低置信度封顶 0.6”，把审计定位为**一票否决器**（识别坏源），
而不是**分级调优器**。
