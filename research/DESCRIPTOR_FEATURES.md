# 分类描述符特征验证（合成受控实验）

## 动机

`research/REAL_DATA_LOO.md` 显示：6 条真实测量点 + one-hot 类别特征时，GP 预测退化。
本实验用**合成受控**场景验证 `descriptors` 机制是否真的能把类别间的相似性带进模型。

## 方法

- `scripts/benchmark_descriptors.py`：
  - 60 个类别，每个类别隐藏一个 2-D 描述符；
  - 真实目标 `y = 60 + 40·exp(−d²/0.08)`，最优点 (0.75, 0.25) 附近（类别 C46）；
  - A 臂：one-hot 特征；B 臂：同一批类别改用 2-D 描述符；
  - 算法 `bayes`，budget 30，batch 6，seeds 0/1/2，其余完全一致。
- 该实验只使用合成函数，结论仅说明**机制有效**，不代表真实化学数据上的收益。

## 结果

| 臂 | best_yield 均值（3 seeds） | 各 seed 最优类别 |
|---|---|---|
| **descriptors** | **99.932** | C46 / C46 / C46（全部命中真最优） |
| one_hot | 99.772 | C47 / C46 / C45（2/3 未命中） |

## 结论

- 描述符让 60 类别空间退化为 2 维连续问题，GP 的样本需求从 ~60 降到 ~10；
- 实现细节：描述符会按维度 min-max 缩放到 [0,1]（避免 MW≈73 这类量纲压倒 logP≈−1），原始值保留在 `descriptors` 中供报告；
- 在同等预算下命中率与稳定性都更好（3/3 vs 1/3）；
- 真实数据的收益仍取决于**描述符质量**（需要可信物性表），因此：
  1. 优先给高基数分类变量配描述符；
  2. 没有描述符时仍可用 one-hot，但要预期样本效率下降。

## 复现

```powershell
py -3 scripts/benchmark_descriptors.py --budget 30 --seeds 0 1 2
```
## 部分描述符表

真实物性表常常只覆盖一部分 choice。此时：

- 已知 choice：min-max 缩放的描述符向量 + `0.0`（unknown 指示位）；
- 未知 choice：零向量 + `1.0`；
- 至少要有一个 choice 命中，否则报错。

这样 GP 仍能在已知类别间利用相似性，同时把“未知类别”单独标记，而不是退化成全 one-hot。
## 描述符质量敏感性（合成受控）

`scripts/benchmark_descriptor_quality.py`：给描述符加 `eps * N(0,1)` 噪声，其余不变
（budget 30，3 seeds）。

| eps | best_yield 均值 | 说明 |
|---|---|---|
| 0.0 | 99.932 | 完美描述符 |
| 0.1 | 99.932 | 几乎无损 |
| 0.25 | 99.870 | 轻微下降 |
| 0.5 | 99.870 | 仍优于 one-hot |
| 1.0 | 99.746 | 与 one-hot 相当 |
| 99（垃圾描述符 / one-hot 对照） | 99.772 | 退化到 one-hot 水平 |

结论：在该受控场景下描述符对噪声**鲁棒**（eps ≤ 0.5 基本无损），
最坏情况不会比 one-hot 更差 —— 因为 min-max 缩放 + ARD 仍能利用残差结构。
真实数据上仍应优先选择可信物性表，但不必因为个别值不精确而放弃描述符。
## Tier C（12 级溶剂）上的实际对比

`scripts/benchmark_tier_c.py`：同一合成 landscape，仅特征编码不同，budget 20、5 seeds。

| 算法 | one-hot best / regret | descriptors best / regret |
|---|---|---|
| `bayes` | 91.858 / 0.513 | **92.020 / 0.351** |
| `tpe` | **90.215 / 2.156** | 84.072 / 8.299 |

结论（重要且诚实）：

- 描述符让 **GP（bayes）** 略微更好（更小的 regret）；
- 但 **TPE 在描述符特征下明显变差** —— TPE 的 Parzen 密度在 one-hot/离散维度上更接近
  其设计假设，压缩成 2 维连续描述符后反而失去结构；
- 因此实践中：**描述符优先搭配 GP 类算法**（bayes/constrained/parego/mfbo/momfbo）；
  没有描述符或要用 TPE 时，保持 one-hot。
## 对路由的影响（正面副作用）

描述符会**缩小 `feature_dim`**（12 级溶剂：12 one-hot → 2 描述符），
因此 router 在高基数分类场景可能从 TPE 转向 GP 类算法。已用测试固定：
10+10 级分类 + 1 连续的上下文，加描述符后 `route()` 返回 `bayes`（无描述符时是 `tpe`）。

若用户显式钉住 `tpe` 而空间含描述符，`step` 会给出
`review_algorithm_for_descriptors` 建议（附 Tier C 实测理由），仅提示不改选择。
## 多目标 + 多保真（12 级溶剂）上的描述符

`mf_solvent`（one-hot，13 维）vs `mf_solvent_desc`（描述符，3 维），
budget 40、3 seeds，可行 HV：

| 算法 | one-hot | descriptors |
|---|---|---|
| momfbo | 1195.3（22.3 全保真点） | 1192.0（25.0） |
| mfparego | 1196.1（30.7） | 1196.6（34.3） |

结论：**在多保真多目标下描述符对 HV 基本中性**（差异 <0.5%，**未检出差异**；按 A4 的 TOST 口径，5 seeds 下 90% CI 跨越 ±δ，故只能说“未检出”，不能说“已证明等价”）；
主要收益是把特征从 13 维降到 3 维（GP 拟合更快、更省候选评估）。
与 Tier C 结论一致：描述符的价值取决于算法与预算，不应一概而论。
## 高基数 + 硬约束场景（12 级溶剂，T ≤ 80）

`scripts/benchmark_solvent_constrained.py`（budget 60，3 seeds，指标 = 可行最优值 /
可行率）：

| 算法 | one-hot 最优 / 可行率 | 描述符 最优 / 可行率 |
|---|---|---|
| `constrained` | **90.394** / 0.683 | **90.377** / **0.917** |
| `bayes` | 84.662 / 0.183 | 82.426 / 0.106 |
| `tpe` | 85.744 / 0.100 | 79.434 / 0.333 |

结论：

1. **约束场景必须用约束感知算法**：`constrained` 的最优值比 bayes/tpe 高 5–6 分，
   可行率也高得多（0.68 vs 0.10–0.18），验证了 router 对带约束问题选 `constrained` 的策略；
2. **描述符让可行率从 68% 提升到 92%**（最优值持平）——在约束紧密时，
   维度更低的描述符特征让 GP 更容易找到可行域；
3. TPE 在描述符下仍然更差（79.4 vs 85.7），与 Tier C 结论一致。

## 复核（Round 291，solvent_constrained，budget 40，2 seeds）

| 编码 | 算法 | 最优可行值 | **可行率** |
|---|---|---|---|
| one-hot | constrained | 90.331 | 0.538 |
| 描述符 | constrained | **90.359**（+0.03%） | **0.875** |
| one-hot | tpe | 83.790 | 0.138 |
| 描述符 | tpe | **84.026**（+0.3%） | **0.475** |

**结论**：

1. **最优值上描述符仍接近中立**（+0.03% / +0.3%），与既有结论一致；
2. **但可行率差异明显**（constrained 0.538 → 0.875；tpe 0.138 → 0.475）——描述符把
   连续约束（如温度上限）表达成了可插值的方向，从而使更多点落在可行域内；
3. 只有 2 seeds、单问题，**不足以改默认**，但足以说明“描述符的价值可能体现在可行率/交付证据
   而不是最优值”，应作为后续复核的观测指标。

## 有功效复核（Round 293，5 seeds，budget 40）

| 编码 | 算法 | 最优可行值 | 可行率 |
|---|---|---|---|
| one-hot | `constrained`（约束感知） | 90.287 | 0.550 |
| 描述符 | `constrained` | **90.357**（+0.08%） | **0.875** |
| one-hot | `bayes`（不看约束） | 85.507 | 0.285 |
| 描述符 | `bayes` | 82.957（**−3.0%**） | 0.150（**更差**） |
| one-hot | `tpe` | 84.195 | 0.115 |
| 描述符 | `tpe` | 76.482（**−9.2%**） | **0.395** |

**结论（比“中立/有增益”更精确）**：

1. **只有约束感知的优化器才受益**：`constrained` 的最优值不变（+0.08%）而可行率 0.550 → **0.875**（相对 +59%）；
2. **约束盲的优化器反而更差**：`bayes` 的最优值 −3.0%、可行率也更低（0.285 → 0.150）——
   描述符增加的维度对不处理约束的模型只是噪声；
3. **`tpe` 是权衡**：可行率升（0.115 → 0.395）但最优值明显掉（−9.2%），不能称为收益；
4. 5 seeds 下方向稳定，因此可作为**条件性建议**：高基数分类 + 绑定约束时，用描述符编码要**同时**选
   约束感知算法（`constrained`/`cqehvi`），否则不如继续用 one-hot。

## 第三个场景：2 目标 + 硬约束 + 高基数分类（Round 294，3 seeds）

为此新增基准 `moo_solvent_constrained` / `moo_solvent_constrained_desc`（同一 landscape，仅编码不同），
用 `cqehvi` 跑 budget 40：

| 编码 | 可行 HV | 可行全保真点数 |
|---|---|---|
| one-hot | **1060.28** | 29.67 |
| 描述符 | 1045.07（**−1.4%**，3 seeds） | **37.0（+25%）** |

**噪声底复核（5 seeds 配对，`scripts/noise_floor.py`）**：逐种子差 −3.00/−23.53/+0.85/+5.40/+2.13，平均 **−3.63（−0.34%）**、sd 11.52、**t = −0.704 < 2.776** → **差异未超出噪声底**（见 `research/NOISE_FLOOR.md`）。因此“HV 不变/略降”的说法有测量支撑，而不是感觉。

**结论（把规则说准）**：

1. 在 MOO + 约束下，描述符的**可行 HV 没有提升**（−1.4%，未检出差异；TOST 判为“不确定”——要证明等价需要 δ ≥ 14.62 HV 或更多 seed），
   但**可行点覆盖 +25%**；
2. 与单目标 `constrained` 的复核（可行率 0.550→0.875、最优值不变）合起来看，
   一致的模式是：**描述符改变的是“覆盖/可行率”，而不是“最好值”**；
3. 因此建议的措辞更新为：高基数分类 + 绑定约束时，用描述符编码**配合约束感知算法**可以提高
   **可行点覆盖**（+25%~+59%），**不要期待最优值/HV 提升**；约束盲算法上则更差。
